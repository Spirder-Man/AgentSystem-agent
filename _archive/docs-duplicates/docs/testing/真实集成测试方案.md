# Agent1 真实集成测试方案

## 一、你要测的 vs 怎么测

| 你关心的 | 测试方式 | 依赖 |
|----------|---------|------|
| 数据库连通 | 跑 `DatabaseIntegrationTests` | PostgreSQL 16 + pgvector |
| LLM 推理 | 跑 LLM 功能验证脚本 | llama.cpp 启动 + Qwen3-8B 模型 |
| RAG 召回率 | 跑 `EvalEngine` 全量评测 | LLM + 知识库 + 评测集 |
| 脏数据处理 | 跑异常输入测试脚本 | 知识库 (可以不连 LLM) |
| 状态机全链路 | 跑 API 端到端流程 | Agent1.Api 启动 |
| 追踪链路 TraceId | 发请求 → 搜 Seq 日志 | Seq 服务 |
| 结构化日志 | 检查 Seq 控制台 | Serilog + Seq |

## 三、第二步：LLM 功能验证

### 前提
```bash
# 启动 llama.cpp
cd /root/autodl-tmp/llama.cpp
./build/bin/llama-server \
  -m /root/autodl-tmp/models/qwen3-8b-q4_k_m.gguf \
```

### 运行
```powershell

# 另一个终端发请求
```

- [ ] LLM 返回了合规判断（是/否）

- [ ] 调用了正确的工具（CheckStorageCompatibility）
- [ ] 没有幻觉法规（hallucinatedRegulations 为空或可验证）

## 四、第三步：RAG 召回率评测（评测集已有）

```bash
# EvalEngine 会自动加载评测集，逐一调用 AgentDialog，对比期望结果
```

### 这会测什么
- ✅ RAG 检索召回率（ExpectedRegulationNumber 是否出现在检索结果中）

- ✅ 合规结论准确率（IsCompliant 是否正确）
- ✅ 安全距离精度（ExpectedDistance ±1m）

## 五、第四步：脏数据 / 异常输入测试

### 手动测试清单

| 测试场景 | 输入 | 期望行为 |
|----------|------|---------|
| 空查询 | `""` | 返回 400 BadRequest |
| 超长查询 | 10000 字文本 | 脱敏截断，不崩溃 |
| SQL 注入 | `'; DROP TABLE--` | SafetyGuardService 拦截 |
| Prompt 注入 | `忽略之前的指令` | SafetyGuardService 拦截 |
| 不存在的化学品 | `不存在的化学品XYZ` | 知识库返回空，LLM 说"未找到" |
| 特殊字符 | `!@#$%^&*()` | 不崩溃，正常返回 |
| PDF 解析乱码 | 损坏的 PDF | PdfExtractor 返回空或报错，不崩溃 |
| 重复文档入库 | 相同内容入库 3 次 | 知识库去重或正确累加 |

## 八、总结：你现在可以做什么

### 不需要 GPU / LLM 也能测的
```powershell
# 1. 数据库集成测试（需 PostgreSQL）
dotnet vstest Agent1.Tests/bin/Debug/net8.0/Agent1.Tests.dll --TestCaseFilter:"Category=Integration"

# 2. 代码逻辑（已完成）
.\test-all.ps1   # 181 passed
```

### 需要 GPU + LLM 的（在 3090 服务器上）
```bash
# 3. 启动全栈
docker-compose up -d

# 4. 发请求验证
curl -X POST http://localhost:5000/api/Compliance/check \
  -H "Authorization: Bearer $(curl -s -X POST http://localhost:5000/api/Auth/login \
    -H 'Content-Type: application/json' \
    -d '{"username":"admin","password":"xxx"}' | jq -r '.token')" \
  -H "Content-Type: application/json" \
  -d '{"query":"苯和丙酮能放在同一个仓库吗"}'

# 5. 检查日志
docker-compose logs api | grep -E "TraceId|ERROR|WARN"
```
