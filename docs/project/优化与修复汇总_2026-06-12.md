## 一、RAG GPU 全链路加速优化（Sprint 1-5）

**目标**：针对 RTX 3090 24GB Linux 环境，将 RAG 检索全链路迁移至 GPU，Precision@K 从 31.7% 提升至 55%+，总延迟降低 75%。

### Sprint 1：嵌入 GPU 加速 + 批量处理

| 文件 | 变更类型 | 说明 |
|------|---------|------|
| `Config/AppConfig.cs` | 新增配置 | `GpuEmbeddingEnabled`、`EmbeddingBatchSize(32)`、`EmbeddingTimeoutSeconds(30)`、`MaxConcurrentEmbeddings(4)` 等 12 项 GPU 配置 |
| `appsettings.json` | 配置同步 | 所有 GPU 配置项默认值 |
| `Services/AI/ILlmService.cs` | 接口扩展 | 新增 `GetEmbeddingsBatchAsync(List<string> texts)` 接口方法 |
| `Services/AI/LlmService.cs` | 核心实现 | `GetEmbeddingsBatchAsync` — 单次 API 调用处理多条文本嵌入（`input` 数组），超时 30s → 自动降级逐条嵌入 |
| `Services/AI/LlmService.cs` | 连接池优化 | 构造函数 `SocketsHttpHandler`：`PooledConnectionLifetime=5min`、`MaxConnectionsPerServer` 可配置 |
| `Services/Knowledge/HybridKnowledgeBaseService.cs` | 批量文档添加 | `AddDocumentsBatchAsync()` — BM25 写入 → GPU 批量嵌入 → PostgreSQL 批量事务入库 |

| `Services/Infrastructure/DatabaseService.cs` | 实现 | `AddChemicalDocumentsBatchAsync`（事务批量 INSERT）、`GetAllChemicalDocumentsWithEmbeddingsAsync`（全量读取）、`ParsePgVectorString`（pgvector `[0.1,0.2]` → `float[]` 解析） |

## 二、RAG 评估体系修复（fix1a-fix3 + eval1-eval3）

### 问题诊断

原始 RAG 评估体系存在六大问题：RAG 返回原文过长导致 Faithfulness 崩塌、Prompt 无格式约束导致结论不可解析、工具描述歧义导致路由失败、空数据被误判为错误、评估维度单一无工程指标。

### 修复清单

| 编号 | 问题 | 文件 | 修复方案 |
|------|------|------|---------|
| **fix1a** | RAG 结果过长导致 Faithfulness 崩塌 | `ChemicalComplianceTools.cs` | 新增 `TruncateChunk` 方法，RAG 返回内容截断至 500 字符，防止 LLM 复述原文 |
| **fix1b** | Prompt 无格式约束 | `appsettings.json` / `AppConfig.cs` | `EvalFastPrompt` / `EvalFastQueryPrompt` 增加【输出格式】指令："每条查询结果用一句话概括，禁止输出法规全文" |
| **fix1c** | Faithfulness 误判 RAG 原文为幻觉 | `EvalEngine.cs` | 新增 `ExtractConclusionContent()` — 过滤 RAG 原文引用块，仅对结论性声明 `[判定:is_compliant=...]` 评估忠实度 |
| **fix2** | `CheckStorageCompatibility` 工具描述歧义 | `appsettings.json` / `AppConfig.cs` / `ToolServiceTests.cs` | Description 显式声明"判断同库储存合规性"，新增 7 个 KeywordTriggers（同库存放/能否同存/混存 等） |
| **fix3** | 空数据被误判为错误 | `ConclusionVerifier.cs` / `EvalEngine.cs` | `VerifyAsync` + `CheckConclusion` 增加 `hasEmptyData` 逻辑，识别"无数据/未检索到/无记录"为正确知识边界识别 |
| **eval1** | 缺少 Answer Relevance 指标 | `EvalEngine.cs` | 新增 `EvaluateAnswerRelevanceAsync()` — LLM 1-5 打分 + 关键词匹配降级 |
| **eval2** | 缺少 Citation Accuracy 指标 | `EvalEngine.cs` | 新增 `EvaluateCitationAccuracy()` — 检查回答中法规编号是否在检索上下文中出现 |
| **eval3** | 缺少工程性能指标 | `EvalEngine.cs` | 每用例 Stopwatch 精确延迟 + Token 估算 + `EngineeringMetrics`（P50/P95/均值） |
