## 1. 速率限制机制

### 1.1 实现架构

```
请求 → RequestIdMiddleware → RateLimitingMiddleware → ... → Response
                                  │
                          IP:Path 限流键
                                  │
                       SlidingWindow (ConcurrentDictionary)
                                  │
                         <100次/分钟? ──否──→ 429 Too Many Requests
                                  │
                                 是
                                  │
                              继续处理
```

### 1.2 核心实现

文件：[RateLimitingMiddleware.cs](file:///d:/桌面/agent/项目/Agent1/Agent1.Api/Middleware/RateLimitingMiddleware.cs)

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `_maxRequests` | 100 | 每个窗口允许的最大请求数 |
| `_window` | 60s | 滑动窗口时长 |

**IP 识别策略（三级优先级）：**

```csharp
// 优先 X-Forwarded-For（反向代理）→ 直连 IP → unknown 兜底
var ip = context.Request.Headers["X-Forwarded-For"].FirstOrDefault()
         ?? context.Connection.RemoteIpAddress?.ToString()
         ?? "unknown";
```

**限流键：`{IP}:{Path}`** — 按 IP + 端点组合限流，比纯 IP 限流更精细，避免单一端点高负载影响其他端点。

**线程安全：** 使用 `ConcurrentDictionary<string, SlidingWindow>` + `lock(window)` 双重保护。`SlidingWindow` 内部用 `List<DateTime>` 存储时间戳，过期自动清理。

**429 响应格式：**

```json
{"error":"请求过于频繁，请 15 秒后重试","retry_after_seconds":15}
```

同时设置 `Retry-After` HTTP 头，客户端可直接编程解析。

### 1.3 生产环境建议

当前实现是**单机内存限流**，适用于单容器部署。多实例场景建议升级为：

- **AspNetCoreRateLimit**：NuGet 包，支持 Redis 分布式计数
- **Nginx rate limiting**：网关层限流，`limit_req_zone $binary_remote_addr zone=mylimit:10m rate=10r/s`
- **Kong / APISIX**：API 网关层插件限流

### 2.4 三层账号配置加载

```
优先级: 环境变量 AUTH_ACCOUNTS_JSON → appsettings.json Auth.Accounts → 开发默认值
```

| 层级 | 来源 | 生产行为 |
|------|------|----------|
| Layer 1 | `AUTH_ACCOUNTS_JSON` 环境变量 | ✅ 优先使用 |
| Layer 2 | `appsettings.json` → `Auth.Accounts` | ✅ 兜底使用 |
| Layer 3 | 硬编码 `admin/admin123` 等 | ❌ **生产环境直接 throw 拒绝** |

### 2.5 密码安全：BCrypt 哈希

```csharp
// 启动时自动升级明文密码
if (!IsBcryptHash(acc.Password) && !string.IsNullOrEmpty(acc.Password))
{
    acc.Password = BCrypt.Net.BCrypt.HashPassword(acc.Password, workFactor: 12);
}
```

- `workFactor: 12` — 每次哈希约 250ms，兼顾安全性和登录体验
- 验证时自动识别 BCrypt（`$2` 开头）vs 明文，平滑过渡

### 2.6 Refresh Token 轮转

流程：
```
客户端请求刷新 → 验证 RefreshToken(SHA256查DB)
                → 原子删除旧 Token(一次性使用)
                → 签发新 AccessToken + 新 RefreshToken
                → 旧 RefreshToken 立即失效
```

DB 存储的是 **SHA256 哈希**，即使数据库泄露也无法直接使用。原始 RefreshToken 仅登录/刷新时返回一次。

### 2.7 授权策略

```csharp
options.AddPolicy("Admin",   policy => policy.RequireRole("admin"));
options.AddPolicy("Auditor", policy => policy.RequireRole("admin", "auditor"));
options.AddPolicy("Viewer",  policy => policy.RequireRole("admin", "auditor", "viewer"));
```

全部使用 `Interlocked.Increment` / `Interlocked.Read` / `Interlocked.Add` 实现 **lock-free 并发更新**，零锁竞争。

```csharp

    Console.WriteLine("⚠️ [慢请求告警] LLM 调用耗时 ...");
```

## 5. 负载测试方案

### 5.1 测试工具架构

文件：[Benchmark/Program.cs](file:///d:/桌面/agent/项目/Agent1/Benchmark/Program.cs)

```
CLI: dotnet run --project Benchmark -- [并发数] [请求数] [BaseUrl]
默认: 并发10 | 每端点20请求 | http://localhost:5000
```

**测试流程：**

```
1. 登录获取 Token + RefreshToken
2. 对每个端点: 预热(3次) → 并发请求(N次) → 统计延迟

测试端点:
  ├── GET  /health/live           (无Auth)
  ├── GET  /health                (无Auth)
  ├── GET  /metrics               (无Auth)
  ├── POST /api/auth/login        (无Auth)
  ├── POST /api/auth/refresh      (需RefreshToken)
  ├── POST /api/compliance/check  (需Bearer)
  ├── GET  /cache/stats           (需Bearer)
  └── GET  /memory/stats          (需Bearer)
```

### 5.2 并发控制

```csharp
// 信号量模式控制并发度
while (tasks.Count(t => !t.IsCompleted) >= Concurrency)
    await Task.Delay(10);
```

非暴力 `Task.WhenAll`，而是控制 in-flight 请求数不超过 `Concurrency`，防止客户端侧成为瓶颈。

### 5.3 统计指标

| 指标 | 说明 |
|------|------|
| `OK / FAIL` | 成功/失败计数 |
| `QPS` | 每秒成功请求数 |
| `Avg` | 平均延迟(ms) |
| `P50 / P95 / P99` | 百分位延迟 |
| `Min / Max` | 最小/最大延迟 |

### 5.4 使用示例

```bash
# 默认参数：并发10，每端点20次请求
dotnet run --project Benchmark

# 高负载：并发30，每端点50次请求
dotnet run --project Benchmark -- 30 50

# 指定目标
dotnet run --project Benchmark -- 10 20 http://localhost:8080
```

### 5.5 CI 集成

在 GitHub Actions 中 `continue-on-error: true` 运行，失败不阻断流水线：
```yaml
- name: Benchmark (non-blocking)
  run: dotnet run --project Benchmark --configuration Release -- 5 20 http://localhost:5000
  continue-on-error: true
```

## 7. 安全配置与最佳实践总结

### 7.1 中间件管线顺序

```
1. GlobalExceptionMiddleware    ← 最外层，捕获所有异常
2. RequestIdMiddleware          ← 注入 X-Request-Id
3. RateLimitingMiddleware       ← 限流（100次/分钟/IP:Path）
4. RequestMetricsMiddleware     ← 指标记录
5. Swagger                      ← 文档
6. CORS                         ← 跨域
7. Authentication (JWT)         ← 身份认证
8. Authorization                ← 权限校验
9. Controllers                  ← 业务处理
```

### 7.2 全局异常处理分层

| 异常类型 | HTTP 状态码 | 说明 |
|----------|------------|------|
| `CircuitBreakerOpenException` | 503 | 熔断器拒绝，响应含 `retryAfter: 30` |
| `OperationCanceledException` | 499 | 客户端断开，不记录错误日志 |
| `TimeoutException` | 504 | 请求超时 |
| `Exception` (兜底) | 500 | 不泄露内部细节，返回 `traceId` 用于排查 |

### 7.3 生产环境 Checklist

| # | 检查项 | 验证方式 |
|---|--------|----------|
| 1 | `.env` 排除出 Git | `git status` 确认无 .env |
| 2 | `JWT_KEY` ≥ 32 字符 | 启动日志无长度警告 |
| 3 | `DB_PASSWORD` 非空非默认 | 启动不报 Exit(1) |
| 4 | `AUTH_ACCOUNTS_JSON` 真实密码 | 登录不用 dev 默认账号 |
| 5 | `ASPNETCORE_ENVIRONMENT=Production` | 健康检查 `/health` |
| 6 | Ollama 在宿主机运行 | `ollama list` 有 qwen3:8b |
| 7 | Docker 非 root | `docker top chemical_agent_api` 显示 appuser |
| 8 | 日志不泄露密码 | `docker logs chemical_agent_api` 检查 |
