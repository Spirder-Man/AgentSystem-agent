## 高频错误分析

> 当前 9 条记录。E018/E019/E025 同属 FC 配置族（Required 策略误用）——E018 是业务评测死循环、E019 是 HyDE 递归卡死、E025 是评分 LLM 重复输出，三者根因相同（Required() 在不需要工具调用的场景被继承），表现不同。E020/E021/E022/E023/E024 同属评测框架缺陷族（白名单不同步 + 判定过松 + 无审计追踪 + 双通道不完整 + 结论提取数据源错误），五 Bug 集中在评测线路暴露：① 白名单过窄导致 info_query 全挂（E020）→ ② 工具未触发使双通道被跳过（E023 根因二）→ ③ 结论提取器从错误数据源取数导致 A 类虚报⚠️（E024）→ ④ 判定过松误判幻觉（E021）→ ⑤ 无审计追踪不可诊断（E022）。根因是「评测路径未与对话路径保持双通道逻辑一致」+「评测框架的多个数据提取点未溯源到明确数据源」。后续需关注：① 新增执行路径时必须对照已有路径做完整性检查；② 代码审查应引入「对称性检查」——同名保护机制在两条路径上的差异必须明确记录或消除；③ FC 策略不应在调用链上盲传——每个 LLM 调用点应显式声明其 FC 策略，禁止默认继承。
