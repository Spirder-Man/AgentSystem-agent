# 远程手动启动与本地联调指南

> **适用环境**：AutoDL GPU 容器（RTX 3090） | **API 监听**：HTTP 52320 / HTTPS 52319

---

## 一、连接远程服务器

```powershell
ssh root@connect.nmb2.seetacloud.com -p 40448
```

---

## 二、启动远程服务

以下按依赖顺序执行，均在远程服务器上操作。

### 1. 同步代码

```bash
cd /root/autodl-tmp/agent-system && git pull
```

### 2. 启动 PostgreSQL

```bash
PGPASSWORD=7758521 pg_isready -h localhost -p 5432 -U postgres -d agent1
# 如果显示 "no response"，启动 PostgreSQL：
pg_ctlcluster 14 main start
# 如果 pg_ctlcluster 不存在，尝试：
pg_ctl -D /var/lib/postgresql/14/main start
```

### 3. 启动 llama-server（LLM 推理）

```bash
nohup llama-server \
  -m /root/autodl-tmp/models/qwen3-8b-instruct.Q4_K_M.gguf \
  --host 0.0.0.0 --port 8080 \
  -c 32768 --gpu-layers 99 \
  > /root/autodl-tmp/logs/llama-llm.log 2>&1 &
```

### 4. 启动 llama-server（Embedding 向量嵌入）

```bash
nohup llama-server \
  -m /root/autodl-tmp/models/nomic-embed-text-v2.Q4_K_M.gguf \
  --host 0.0.0.0 --port 8081 \
  --embeddings --gpu-layers 99 \
  > /root/autodl-tmp/logs/llama-embed.log 2>&1 &
```

### 5. 编译 API

```bash
cd /root/autodl-tmp/agent-system && dotnet build
```

### 6. 启动 API（HTTPS 52319 / HTTP 52320）

```bash
nohup env DOTNET_ENVIRONMENT=Production \
  JWT_KEY=qazwsxedcrfvtgbyhnujmikolpqazwsx \
  DB_PASSWORD=7758521 \
  AUTH_ACCOUNTS_JSON='[{"Username":"admin","Password":"7758521","Role":"admin"},{"Username":"auditor","Password":"7758521","Role":"auditor"}]' \
  dotnet run --project Agent1.Api --environment Production \
  > /root/autodl-tmp/logs/agent1-api.log 2>&1 &
```

### 7. 验证 API 存活

```bash
# 心跳轮询（最多等 60s，每 3s 一次）
for i in $(seq 1 20); do
  curl -sk https://localhost:52319/health/live && echo " OK" && break
  sleep 3
done
```

## 三、本地建立 SSH 隧道

在 **本地 Windows** 新开一个 PowerShell 窗口，保持运行：

```powershell
ssh -L 15000:localhost:52319 root@connect.nmb2.seetacloud.com -p 40448 -N
```

> 输入密码后窗口无输出是正常的（`-N` 不执行远程命令），挂着不要关。
>
> 链路：`localhost:15000` → SSH → 远程 `localhost:52319`（HTTPS）

---

## 四、启动本地前端

### 配置文件（已就绪，无需修改）

`.env`：
```
VITE_ENABLE_MOCK=false
VITE_PROXY_TARGET=https://localhost:15000
```

`vite.config.ts`：通过 `loadEnv` 读取 `VITE_PROXY_TARGET`，所有代理路径（`/api`、`/health` 等）统一指向该地址，`secure: false` 跳过自签名证书校验。

### 启动

```powershell
cd d:\桌面\agent\项目\Agent1\agent1-web
npm run dev
```

访问 `http://localhost:5173`。

## 五、完整链路图

```
浏览器 (http://localhost:5173)
  │  GET/POST /api/...
  ▼
Vite Dev Server (5173)
  │  proxy → https://localhost:15000  (secure: false)
  ▼
SSH 隧道 (15000 → 远程 52319)
  │  TCP 转发
  ▼
ASP.NET Core API (HTTPS 52319)
  │  Semantic Kernel
  ▼
llama-server LLM (8080) + Embedding (8081) + PostgreSQL (5432)
```

## 七、常用诊断命令

```powershell
# 本地 → 检查 Vite 是否在跑
netstat -ano | findstr ":5173"

# 本地 → 检查 SSH 隧道是否在跑
netstat -ano | findstr ":15000"

# 本地 → 直连测试 API（绕过 Vite）
curl.exe -k https://127.0.0.1:15000/health/live

# 远程 → 检查 API 是否在跑
curl -sk https://localhost:52319/health/live

# 远程 → 查实时日志
tail -f /root/autodl-tmp/logs/agent1-api.log
```
