## 一、全局架构映射：前端三层 vs 后端六层

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          AGENT1 全栈架构对齐                                 │
├─────────────────────────────────────┬───────────────────────────────────────┤
│         前端 agent1-web             │         后端 .NET 8                    │
│        (Vue 3 + Vite 5)             │   (ASP.NET Core + Semantic Kernel)    │
├─────────────────────────────────────┼───────────────────────────────────────┤
│                                     │                                       │
│  [视图层] pages/  17页面            │  [第1层] 表现层 (Controller)          │
│     ↓ 组件渲染                     │     ↑ JSON Response                   │
│  [组件层] components/  40+组件      │  [第2层] 模块调度层 (ModuleDispatcher) │
│                                     │                                       │
│  [状态管理层] stores/  8 Pinia      │  [第3层] 业务编排层 (AgentDialog)     │
│     ↓ mutation/query               │     ↓                                 │
│  [数据获取层] @tanstack/vue-query   │  [第4层] 核心业务层 (LlmService)      │
│     ↓ axios                        │     ↓                                 │
│  [HTTP 层] lib/axios.ts + JWT      │  [第5层] 基础设施层 (Database)         │
│     ↓ HTTPS                        │     ↓                                 │
│  [Mock 层] MSW handlers (开发模式)  │  [第6层] 外部系统层 (llama.cpp等)     │
│                                     │                                       │
└─────────────────────────────────────┴───────────────────────────────────────┘
```

### 1.1 关键架构契约

| # | 前端层 | 后端层 | 契约内容 | 当前状态 |
|---|--------|--------|---------|:--------:|
| 1 | **路由守卫** `router.beforeEach` | **第1层** Middleware `[Authorize(Policy)]` | 前端先过滤角色，后端二次验证 JWT | ✅ |
| 2 | **页面路由** `/compliance` | **第2层** ModuleDispatcher → `ComplianceCheck(8)` | 路由路径与 ModuleType 一一对应 | ✅ |
| 3 | **Pinia action** `checkCompliance()` | **第3层** AgentDialog.ExecuteEvalFastAsync | Store 调用链 = AgentDialog 6步流水线 | ✅ |
| 4 | **axios POST** `/api/Compliance/check` | **第4层** LlmService.InvokeNonStreamingWithRetryAsync | FC调用链：prompt → SK Kernel → llama.cpp | ✅ |
| 5 | **缓存策略** `staleTime: 30s` | **第5层** ResponseCacheService (TTL 5min) | 前端短缓存 + 后端长缓存双层 | ✅ |
| 6 | **健康检查** `useQuery(['health'])` | **第6层** llama.cpp + PostgreSQL + Embedding | 前端显示服务就绪状态 | ✅ |

## 二、第1层对接：表现层 (Presentation Layer)

### 2.1 三通道入口统一认证

```
┌─────────────────────────────────────────────────────────────────┐
│  前端入口: LoginPage.vue                                         │
│                                                                  │
│  POST /api/Auth/login { username, password }                     │
│         ↓                                                        │
│  [后端第1层] AuthController.Login()                               │
│         ↓                                                        │
│  JWT Token 生成 (密钥: DB_PASSWORD 环境变量)                      │
│         ↓                                                        │
│  Response: { token, refreshToken, username, role, expiresAt }    │
│         ↓                                                        │
│  [前端] authStore.login() → 存储 token → 路由守卫放行             │
│         ↓                                                        │
│  [axios拦截器] 每次请求自动添加 Authorization: Bearer {token}     │
│         ↓                                                        │
│  [后端 Middleware] JWT Bearer 验证 → [Authorize(Policy)] 角色检查  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 前端角色权限 ↔ 后端 Policy 对齐表

| 前端角色 | 后端 Policy | 可访问路由 | 后端中间件行为 |
|----------|------------|-----------|--------------|
| `admin` | `Admin` + `Auditor` | 全部 17 页面 + 审计日志 + 系统管理 | 所有 `[Authorize]` 通过 |
| `auditor` | `Auditor` | 除审计日志/系统管理外全部 | GET/POST 业务API通过 |
| `viewer` | `Viewer` (预留) | 仅 `/login` + `/403` | 当前: 全部 API 返回 401 |

### 2.3 中间件对齐

| 前端处理 | 后端 Middleware | HTTP状态码 | 前端行为 |
|----------|---------------|:---------:|---------|
| axios 响应拦截器 | GlobalExceptionMiddleware | 500 | `ElMessage.error('服务异常')` |
| axios 响应拦截器 | RateLimitingMiddleware | 429 | `ElNotification` 含倒计时 |
| axios 响应拦截器 | TokenBlacklistMiddleware | 401 | 自动刷新 token → 失败跳登录 |
| 路由守卫 `beforeEach` | `[Authorize]` Attribute | 403 | 重定向 `/403` |
| — | RequestIdMiddleware | — | 响应头 `X-Request-Id` (用于日志溯源) |
| — | RequestMetricsMiddleware | — | Prometheus 指标采集 |

## 四、第3层对接：业务编排层 (Orchestration Layer)

### 4.1 AgentDialog 6步流水线 → 前端加载状态同步

```
后端 AgentDialog (6步)          前端 UI 状态
══════════════════════          ═══════════════
[1] PreprocessAsync             → loading = true, progress = 10%
    输入清理 + 安全拦截              (安全拦截: 红色提示)

[2] RouteIntent                 → progress = 30%
    意图分类 → ModuleType          (判断使用哪个 Controller)

[3] LoadContextAsync             → progress = 40%
    会话 + 记忆 + 用户画像加载       (无直接UI变化)

[4] ExecuteBusinessAsync         → progress = 50-80%
    LlmService.InvokeNonStreaming  "推理中...预计 8s"
    → SK Auto FC → 工具调用         ToolCallChain 逐步点亮
    → 工具结果返回                  RegulationRefPanel 逐步填充

[5] SaveSessionAsync             → progress = 90%
    会话保存 → AuditService 记录    (无直接UI变化)

[6] FormatOutput                 → progress = 100%, loading = false
    双通道结果:                     ├─ RegulationRefPanel (结构化)
    法规引用 + LLM解释               └─ LlmExplanationPanel (Markdown)
```

### 4.2 EvalEngine 评测链路 → 前端（Console 专用，API不暴露）

```
EvalEngine.RunComplianceEvalAsync()
  Layer1: FC就绪性检查 (5条诊断用例)
    → 结果不入前端
  Layer2: 逐条业务评测 (63条)
    → eval_reportXXX.json
    → 前端仪表盘可读取 eval_report 统计展示
```

```

  ├─ 推理耗时: 后端返回 latencyMs → 前端显示 "查询耗时 Xs"

  ├─ 数据回显: 巡检计划/工单列表/资产台账 均来自 DB 查询
  └─ 审计哈希链: /audit → 前端显示 "哈希链状态: ✅ 完整 (42条)"

  └─ RAG检索质量: 后端返回 ragQuality → 前端合规自查页角标
```

```typescript
import { describe, it, expect, beforeEach } from 'vitest';
import { setActivePinia, createPinia } from 'pinia';
import { useAuthStore } from '@/stores/auth';

describe('authStore', () => {
  beforeEach(() => { setActivePinia(createPinia()); });

  it('login should set token and role', async () => {
    const store = useAuthStore();
    // Mock axios POST /api/Auth/login
    await store.login('admin', 'password');
    expect(store.isAuthenticated).toBe(true);
    expect(store.role).toBe('admin');

  it('hasPermission should respect role hierarchy', () => {
    const store = useAuthStore();
    store.role = 'admin';
    expect(store.isAdmin).toBe(true);
    expect(store.isAuditor).toBe(true);
  });
});
```
