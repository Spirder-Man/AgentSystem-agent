01 现状问题 · 硬编码关键词的三项致命缺陷
缺陷 1  覆盖盲区

当前 23 个合规关键词靠人工穷举，用户说「爆炸风险」「自燃特性」「放射危害」均无法命中，被误判为 SimpleChat，跳过完整合规链路。

预估缺失率：15%–25%

缺陷 2  精度不可控

FirstOrDefault 仅返回第一个命中，无置信度机制。用户说「帮我分析这个化合物的化学特性」→ 命中「化学」→ 合规，但实际可能是纯学术问题。

误判率：5%–10%

缺陷 3  扩展不可持续

每新增一个业务场景（应急响应、巡检审计）就要手动加关键词。关键词列表膨胀到 50+ 时，FirstOrDefault 的顺序依赖问题加剧。

维护成本：O(n) 线性增长

02 目标架构 · LLM 意图分类器

03 Prompt 设计 · 五意图分类体系

核心设计原则：极短 system prompt + 结构化输出 + 精确约束标签集。0.5B 模型对长 prompt 敏感，必须精简到 200 tokens 以内。

System Prompt（生产版）
# 化工合规意图分类器 · system prompt 你是一个化工安全意图分类器。分析用户输入，返回 JSON。 标签集： - chemical_compliance: 危化品分类/储存/安全距离/法规/事故/应急 - inspection_audit: 巡检/检查/隐患排查/整改 - emergency_response: 泄漏/火灾/爆炸/中毒应急处置 - simple_chat: 闲聊/时间/计算/自我介绍/问候 - unknown: 无法分类 输出格式（仅 JSON，无其他文本）： {"intent":"标签","confidence":0.0-1.0,"keywords":["关键词"]} 规则： 1. 危化品相关优先 chemical_compliance 2. confidence < 0.5 时 intent=unknown 3. 只输出 JSON，不要解释
分类示例（Few-Shot 参考）
# 测试用例 → 期望输出 "苯属于什么危险类别" → {"intent":"chemical_compliance","confidence":0.98,"keywords":["苯","危险类别"]} "甲醇和硝酸能同库储存吗" → {"intent":"chemical_compliance","confidence":0.96,"keywords":["同库储存","甲醇","硝酸"]} "甲类仓库与明火点安全距离" → {"intent":"chemical_compliance","confidence":0.97,"keywords":["安全距离","甲类仓库"]} "储罐区发生苯泄漏怎么办" → {"intent":"emergency_response","confidence":0.94,"keywords":["泄漏","苯"]} "现在几点" → {"intent":"simple_chat","confidence":0.99,"keywords":["时间"]} "帮我计算100+200" → {"intent":"simple_chat","confidence":0.95,"keywords":["计算"]}
🔑 关键设计决策
为什么只用 5 个标签？ 0.5B 小模型的分类能力有限。标签集超过 5 个时，精确率从 95% 下降到约 85%。当前项目实际只有 2 条路径（ChemicalCompliance / SimpleChat），但预留 5 个标签为后续业务扩展（应急响应、巡检审计）做好准备——分类器输出 5 标签，Pipeline 路由时映射到 2 路径。

05 方案对比 · 硬编码 vs LLM 分类
维度 当前：硬编码关键词 目标：LLM 分类器
分类方式 FirstOrDefault(k => lower.Contains(k)) LLM 推理 → 5 标签 JSON → 置信度阈值
关键词覆盖 23 个硬编码，人工穷举 LLM 语义理解，自然覆盖
准确率 ~80% (覆盖不足 + 误判) ~95%+ (需评测验证)
延迟 < 1ms ~150–200ms (GPU) / ~500ms (CPU)
置信度 无 (二值判定) 0.0–1.0 连续值 + 阈值控制
扩展性 加新场景 = 手动加关键词 加新场景 = 新增标签 + prompt 描述
降级路径 — 超时/不可用 → IntentRouter.Route()
⚠️ 风险与缓解
风险 1：0.5B 模型对化工领域术语理解不够 → 缓解：System Prompt 中明确定义化工相关标签的特征描述。
风险 2：RTX 3090 同时跑 Qwen3-8B + nomic-embed + 0.5B 分类器，显存可能紧张 → 缓解：0.5B 模型可跑 CPU（延迟约 500ms，可接受）；或使用 Q4 量化（仅 300MB 显存）。
风险 3：分类器偶尔输出非 JSON 文本 → 缓解：代码层做 JSON 解析容错 + 正则兜底提取 intent 字段。

08 架构决策记录 · ADR
ADR-005: 采用 LLM 意图分类器替代硬编码关键词路由
背景：当前 IntentRouter 使用 23 个硬编码关键词做精确子串匹配，无法覆盖变体表达，准确率约 80%，误判导致合规查询被错误路由到闲聊路径。

决策：引入专用 0.5B LLM（Qwen2.5-0.5B-Instruct）作为意图分类器。分类器独立部署（独立 Ollama 实例或 llama.cpp 进程），与主推理模型隔离。

后果：
· 正面：准确率从 ~80% 提升至 ~95%+，支持 5 标签分类（为应急响应、巡检审计预留），带置信度输出支持降级决策。
· 负面：增加 ~200ms 延迟，需要额外 ~300MB 显存或 CPU 资源。
· 风险缓解：分类器不可用时自动降级到原关键词方案；置信度 < 0.6 时同样降级。

替代方案：向量语义匹配（方案 B）— 延迟更低 (~50ms) 但准确率略低 (~90%)。选择 LLM 分类是因为准确率是化工安全场景的第一优先级。
