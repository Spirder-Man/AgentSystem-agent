## 一、全景：三层器官 + 请求主干道

```
┌─────────────── agent1-web（前端·摄入口）───────────────┐
│ Vue3 页面 → src/api/* → Vite代理(/api) → :5001          │
│ Mock模式：MSW 拦截（src/mocks/），不出浏览器              │
└─────────────────────────┬───────────────────────────────┘
                          ▼
┌─────────────── Agent1.Api（心脏瓣膜·HTTP层）─────────────┐
│ Middleware 顺序：RequestId → 限流 → Token黑名单 → 指标    │
│ 15个Controller → 注入 Agent1 核心服务                     │
│ ScanProgressService：扫描202+轮询（#4）                   │
└─────────────────────────┬───────────────────────────────┘
                          ▼
┌─────────────── Agent1（核心器官·推理与数据）──────────────┐
│ IntentRouter → AgentDialog → LlmService(llama.cpp)       │
│ 工具层 ChemicalComplianceTools ⇦ 三级降级瀑布             │
│ RAG层 ChemicalRAG ⇦ BM25/向量混合检索                    │
│ 出口闸门：双通道管线 + OutputValidator 白名单              │
└──────┬──────────────┬──────────────┬─────────────────────┘
       ▼              ▼              ▼
   PostgreSQL      SQLite         进程内存
   （主库）      （兜底血库）    （启动时充血）
```

请求主干道（合规提问为例）：
`ComplianceController` → `AgentDialog.ExecuteAsync` → IntentRouter 裁剪工具集（9→4）→ LlmService（FC=Auto，流式+死循环检测）→ 工具调用 → 双通道管线（FactExtractor/OutputSanitizer/ResponseMerger）→ `OutputValidator.EnforceLibraryWhitelist` → 返回。

## 二、L0 大动脉（数据端到端链路）

### 动脉 A：非结构化条文 → RAG 检索

```
knowledgebase/ 五子目录（仅远程存在）
  国标/ 化工专业条例/化工专业条例/ 园区规则/ 历史案例/ H166—…/
    │ 入口①全量 ChemicalRAG.LoadKnowledgeBaseAsync（启动时，ChemicalRAG.cs#L132）
    │ 入口②增量 LoadKnowledgeBaseIncrementalAsync（POST /api/knowledgebase/incremental-load）
    │ 两入口共用统一单文件管线 ProcessSingleFileAsync（PDF/DOC/DOCX/TXT 按扩展名分派）
    │ 提取(PdfExtractor/DocExtractor) → 清洗(TextCleaner) → 切块(SemanticChunker)
    ▼
GarbledTextDetector 乱码闸门（三规则确定性拒收，#5 修复）
    ▼
PG: knowledge_documents（source_path UNIQUE）+ knowledge_chunks（含向量，ON DELETE CASCADE）
    │ 启动时：已有分块>0 → 快速模式跳过文件扫描，直接充血
    │ 增量更新场景：先按 source_path 删旧记录（CASCADE 清分块）再重插
    ▼
内存 BM25/向量索引（HybridKnowledgeBaseService）
    ▼
消费者：ChemicalComplianceTools RAG工具 / KnowledgeBaseController 检索接口
```

- 路径解析：`appsettings.json KnowledgeBase.BasePath="knowledgebase"`，`ResolveKnowledgeBasePath` 多锚点探测特征子目录（ChemicalRAG.cs#L74）。
- 增量支线（2026-07-29 重构）：file_tracker.json（绝对路径→LastWriteTimeUtc）全量/增量两路径均维护；删除键=插入键（GetRelativeSourcePath 共用）；处理失败不入 tracker 下次重试；回归测试 KnowledgeIncrementalLoadTests（T1-T6）。
- ⚠️ 存量病灶：快速模式使早期入库的乱码块常驻（60 条分块内），闸门只拦增量。

## 三、L1 静脉（模块级关键结构）

### 静脉 1：结构化查询三级降级瀑布（ChemicalComplianceTools.cs#L691-L756）

```
Level 1  SQLite 兜底库(_chemDb)      ← 动脉C   [DATABASE_HIT] 字段最全(含clause)
Level 2  ChemicalSubstanceDatabase   ← 动脉B   [DATABASE_HIT] ⚠️名为Database实为PG门面
Level 3  工具类内硬编码字典            ← 代码常量 [DICTIONARY_HIT] 质量降级
兜底     FALLBACK 话术                          quality-rules R001 禁止入缓存
```

⚠️ 反直觉：SQLite 排 Level 1（历史原因：字段更全），PG 图谱排 Level 2。

### 静脉 2：出口双通道闸门（回答离开系统前的最后血管）

```
LLM原始输出 → FactExtractor 事实提取 → OutputSanitizer（当次工具返回动态白名单）
           → ResponseMerger 合并 → OutputValidator.EnforceLibraryWhitelist
             （库内全集静态白名单=动脉B法规版本∪动脉C种子∪硬编码字典 三源并集，
              库外GB号→【待核实】标注而非删除，幂等保护，#2）
```

### 静脉 3：记忆缓存旁路（绕过 LLM 的短路血管）

```
写入：工具结果 → IsFallbackContent(R001正则+ToolQualityContext) → 拒兜底话术
读取：TryAnswerFromMemory → R002 置信度门禁 → 低质量缓存不得直接作答
保鲜：GetEffectiveTtl 分级TTL（RAG/DB命中10min，字典5min，兜底0）
预热：WarmupFromEvalSet ← 动脉D 评测集（旁路消费者，曾漏升级 #7）
```

### 静脉 4：推理防御链（Agent1/Services/AI + Dialog）

```
IntentRouter 预判裁剪工具集 → LlmService FC=Auto(防死循环)/HyDE FC=None(防递归)
→ 流式输出三维死循环检测（复读/符号喷射/长度超限）
→ AgentDialog 内部状态走私有字段 _lastToolResults/_lastToolPlan（#9，
   Obsolete 属性只读透出仅供外部兼容）
```

### 静脉 5：API 层长任务血管（#4）

```
POST /api/Dashboard/scan → 已在跑?409 : Task.Run后台 + 立即202(scanId)
GET  /api/Dashboard/scan/status ← ScanProgressService 单例快照
前端 DashboardPage 2s 轮询直至 running=false
（InspectionController /scan 为确定性规则引擎，保持同步，勿动）
```

## 五、检测与辅助系统（非循环器官——只抽血化验，不参与供血）

> 判定标准：参与运行时数据流的是**器官**（入 L0/L1 动静脉）；只消费生产代码/API/数据做验证的是**检测设备**（登记于此，契约变更时必须联动检查）；与运行时无关的是**死组织**（见第六节不入图清单）。

| 检测设备 | 血管接入点（它抽谁的血） | 变更联动规则 |
|---------|------------------------|-------------|
| `Agent1.Tests/`（xUnit，1500+ 条） | 直接引用 Agent1 + Agent1.Api 全部代码；`Stubs/` 四个桩仿真动脉B/存储 | 任何 L2/L3 契约变更必查对应测试；**StubChemicalKnowledgeGraph 在同源拷贝登记表内**（改动脉B/C 数据必同步） |
| `ArchitectureTest/`（架构收敛门禁） | 直接引用 Agent1 程序集，7 项检查（收敛/IntentRouter纯分类/统一分发/线性管线/无硬编码等），CWD 回溯到 sln 根读文件（Program.cs#L19-L22） | 删改 Agent1 文件结构 / 管线编排时必跑；它检查"文件存在性"，重命名文件会击穿它 |
| `Benchmark/`（性能基准） | 纯 HTTP 客户端打 API（默认 :5000，Program.cs#L9），登录→压测健康/认证/业务端点 | 只耦合 **API 契约**（路由/登录字段 username/password/token/refreshToken）；改 AuthController 响应结构会击穿它 |
| `agent1-web/e2e/` + `e2e-real/`（Playwright） | e2e 打 MSW Mock；e2e-real 经 SSH 隧道打真实 API | 前后端字段契约变更时与 MSW mock 一起联动（见同源拷贝登记表） |
| `scripts/run_eval_pipeline.ps1` | 驱动 EvalEngine 吃动脉D 评测集，产出 eval_reports/ | 评测集格式升级时联动（#7 教训的第三个消费者） |
