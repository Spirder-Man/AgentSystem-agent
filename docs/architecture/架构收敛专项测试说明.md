
# 工业AI Agent - 架构收敛专项测试说明

> **版本**: v2.0 | **更新**: 2026-07-20
> **变更**: 从 v1.0 (7验证点/ModuleType 1-7) 扩展至 v2.0 (12验证点/全部12 ModuleType + 前端对接 + CI卡口)

## 测试目标

本测试套件专门用于验证架构重构后的**线性架构收敛**成果，重点验证四大范式模块（CoT/ReAct/Reflection/RAG）及全部 12 种 ModuleType 是否完全融入统一体系，并确保前端 agent1-web 与后端六层架构正确对接。

---

## 核心验证点（7个）

### 1. 【核心重点】四大范式模块集成验证
- 验证CoT/ReAct/Reflection/RAG模块（1-6）完全融入统一体系
- 都实现IInferenceModule接口
- 都通过ModuleFactory统一创建
- 都通过ModuleDispatcher统一调度
- 都使用统一服务注入（ILlmService、ISessionService）
- 无独立运行逻辑、完全融入统一体系

### 2. IntentRouter纯归类验证
- 只返回意图枚举（SimpleChat/IndustrialDiagnostic）
- 不执行业务分支逻辑
- 能正确识别简单对话和工业诊断意图

### 3. 统一调度验证
- 所有模块（1-7）都通过ModuleDispatcher创建和执行
- ModuleFactory覆盖所有7个ModuleType
- Program.cs使用统一调度

### 4. 6步线性流水线验证
- 预处理 → 意图归类 → 上下文加载 → 业务执行 → 会话保存 → 输出
- 每个步骤都有完整实现
- 有流水线执行标记

### 5. 统一基础设施验证
- 所有模块共用同一套SessionService
- 所有模块共用同一套MemoryService
- 所有模块共用同一套LlmService
- 所有模块共用同一套ToolService

### 6. 无硬编码验证
- 验证所有回复由LLM动态生成
- 无固定文案和硬编码回复
- 四大范式模块推理逻辑无硬编码Prompt

### 7. 架构收敛文件验证
- 旧文件已删除（5个）
- 新文件存在（3个）
- ModuleType已收敛到12个模块

### 8. 🆕 扩展模块集成验证（ModuleType 8-10）
- ComplianceCheck (8) 实现 IInferenceModule 接口
- TicketFollowup (9) 实现 IInferenceModule 接口
- RegulatoryAudit (10) 实现 IInferenceModule 接口
- 都通过 ModuleFactory 统一创建
- 都通过 ModuleDispatcher 统一调度
- 都使用统一服务注入（ILlmService、IKnowledgeBaseService）
- 状态机（工单流转/合规发现）不依赖具体实现

### 9. 🆕 预留模块接口验证（ModuleType 11-12）
- EmergencyResponse (11) ModuleType 枚举已定义
- KnowledgeGraph (12) ModuleType 枚举已定义
- ModuleFactory 的 switch 分支已预留
- 无未处理的 ModuleType 导致运行时崩溃

### 10. 🆕 前端-后端架构收敛验证
- 前端路由守卫检查 authStore.hasPermission() 对齐后端 RBAC 三层角色
- 前端每个页面路由对应一个后端 Controller（见映射表）
- 前端 API 类型定义 types/api.ts 与后端 swagger.json 字段名一致
- 前端 MSW Mock 数据结构与后端 API 响应格式一致
- Vite Proxy 代理目标端口与后端 launchSettings.json 端口一致（5000）
- 前端 Axios 拦截器 401/403 处理与后端 Middleware 返回码对齐

### 11. 🆕 六层架构跨层契约验证
- 第1层→第2层: Controller 通过 DI 获取 ModuleDispatcher（非 new）
- 第2层→第3层: ModuleDispatcher 仅调用 IInferenceModule.RunAsync()
- 第3层→第4层: AgentDialog 仅通过 ILlmService 接口调用
- 第4层→第5层: ChemicalComplianceTools 仅通过 IKnowledgeBaseService 获取数据
- 第5层→第6层: DatabaseService 的 Npgsql 连接串仅从 AppConfig 读取
- 跨层禁止: 第1层(Controller) 不可直接调用第4层(LlmService)
- 跨层禁止: 第4层(ChemicalComplianceTools) 不可直接访问第6层(HttpClient直调Ollama)

### 12. 🆕 CI/CD 架构卡口验证
- GitHub Actions ci.yml 包含 ArchitectureTest 步骤
- 架构收敛测试失败时必须阻断构建（CONTINUE_ON_ERROR=false）
- 覆盖率门禁阈值在 coverlet 配置中明确定义 (60%)
- 前端测试 Job 必须有实际测试执行（非空跑）
- Docker 镜像构建使用多阶段 Dockerfile（不包含源代码）
- Staging 部署使用 docker-compose.yml + docker-compose.staging.yml 覆盖模式

## 快速开始

### 前置要求

- .NET 8.0 SDK已安装
- 项目已重构完成

### 执行步骤

1. **编译主项目**（如果还没编译）
```bash
cd Agent1
dotnet build --configuration Release
```

2. **进入测试项目目录**
```bash
cd ArchitectureTest
```

3. **编译测试项目**
```bash
dotnet build --configuration Release
```

4. **运行架构收敛专项测试**
```bash
dotnet run --configuration Release
```

5. **查看测试报告**

测试完成后会在ArchitectureTest目录下生成：
```
架构收敛测试报告.txt
```

### Q: 部分测试失败怎么办？

### Q: 四大范式模块测试失败？
A: 检查ModuleType.cs是否包含7个模块，ModuleFactory是否包含所有创建逻辑
