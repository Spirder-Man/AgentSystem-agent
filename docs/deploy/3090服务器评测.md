### 2.4 阶段 2：Ollama Segfault 诊断与放弃（14:40 - 15:30）

| 时间 | 排查方向 | 操作 | 结论 |
|------|----------|------|------|
| 15:00 | 架构错误？ | `uname -m` → `x86_64` | ✅ 架构正确 |

| 15:06 | CPU 指令集？ | **`grep -o 'avx2\?'` → 只匹配到 `avx`（误判！）** | ⚠️ 正则 `?` 导致误判 |

## 八、经验教训与建议

### 8.1 部署经验法则

| 编号 | 法则 | 说明 |
|------|------|------|
| 1 | **"APT 优先于 curl 脚本"** | 国内环境安装 .NET SDK 优先用 APT，`dotnet-install.sh` 直连 CDN 极易超时 |
| 2 | **"sudo 不可用时用 su"** | `su - postgres -c "psql ..."` 替代 `sudo -u postgres` |
| 3 | **"PowerShell 用 $env"** | `$env:USERPROFILE` 而非 `%USERPROFILE%` |
| 4 | **".gitignore 防子目录误伤"** | `memory/` → `/memory/` 仅匹配根目录 |
| 5 | **"上传先 find"** | JupyterLab 上传后始终 `find / -name 'file*'` 定位 |
| 6 | **"flags 看全行"** | `grep flags /proc/cpuinfo \| head -1`，不用简化的 regex |
| 7 | **"下载走本地"** | 大文件始终走 Windows 本地下载 + JupyterLab 上传 |
| 8 | **"CMake 全显式"** | CUDA 编译必须同时指定 `GGML_CUDA=ON` + `CMAKE_CUDA_COMPILER` + `CMAKE_CUDA_ARCHITECTURES` |
| 9 | **"404 走 WebSearch"** | GGUF 文件名猜测极易出错，直接搜索 `模型名 GGUF bartowski` |
| 10 | **"嵌入用 F16"** | 嵌入模型不建议量化，全精度保证检索准确率 |
| 11 | **"SQL 用 /tmp"** | postgres 用户无法访问 /root，SQL 脚本复制到 /tmp/ |

### 8.2 评测经验总结

1. **知识库覆盖是 RAG 性能的天花板**：GB50160 缺失直接导致安全距离 0/8，知识库文档必须与评测用例对齐
2. **LLM 输出格式对结论验证器极其敏感**：GB30000 文档让 LLM 输出了正确结论但格式不匹配，导致 0/15 误判
3. **工具描述即路由规则**：Function Calling 本质是 Prompt Engineering，工具描述每句话都可能改变路由行为
4. **单文档多值场景需要上下文感知**：所有距离放一个文档时，`ExtractDistanceFromText` 必须根据 `facilityType` 缩小匹配窗口
