> **日期**：2026-06-25

> **分支**：`linux原生编译模型llama.cpp`

## 一、问题全景

算力机重启后四大服务全部停止，恢复过程中共遇到 **5 类问题**：

| # | 问题 | 根因 | 修复 |
|:--:|------|------|------|
| 1 | PostgreSQL 启动命令适配 | AutoDL 容器无 systemd，`service` 命令路径不同 | `su - postgres -c "pg_ctlcluster 16 main start"` |
| 2 | 健康检查误用 Ollama 命令 | 项目已切换 llama.cpp，但健康检查记忆未更新 | 改用 `curl localhost:8080/health` / `:8081/health` |
| 3 | Program.cs 编译错误（CS1529） | 损坏的 commit `876aa8d` 被合并到 `linux原生编译模型llama.cpp` | `git checkout b4faca7 -- Agent1.Api/Program.cs` |
| 4 | API 启动缺少环境变量 | `DOTNET_ENVIRONMENT=Production` 下未传 `JWT_KEY` / `DB_PASSWORD` | 启动命令显式设置三个环境变量 |
| 5 | Kestrel HTTPS 绑定失败（端口无监听） | Production 模式 + launchSettings.json 强制 HTTPS，无证书导致 Kestrel 静默失败 | 加 `--no-launch-profile --urls http://0.0.0.0:5000` |

## 二、逐项排障过程

### 2.1 PostgreSQL 启动

**现象**：
```bash
service postgresql start  # 失败
pg_isready                # /var/run/postgresql:5432 - no response
```

**根因**：AutoDL 容器使用 `pg_ctlcluster` 管理 PostgreSQL，无 systemd 支持。

**修复**：
```bash
su - postgres -c "pg_ctlcluster 16 main start"
```

---

### 2.2 llama-server 健康检查命令错误

**现象**：误用 `curl http://localhost:11434/api/tags`（Ollama 命令）。

**根因**：项目已强制收敛到 llama.cpp + GGUF，LLM 端口 8080、Embedding 端口 8081。

**正确命令**：
```bash
# LLM 服务
curl http://localhost:8080/health     # → {"status":"ok"}

# Embedding 服务
curl http://localhost:8081/health     # → {"status":"ok"}
```

---

### 2.3 Program.cs 损坏（CS1529 等）

**现象**：
```
Program.cs(607,1): error CS1529: A using clause must precede all other elements
Program.cs(616,17): error CS0116: A namespace cannot directly contain members
Program.cs(639,1): error CS8803: Top-level statements must precede namespace
```

**根因**：commit `876aa8d` 的 Program.cs 使用 Write 工具生成时产生了重复/损坏内容（1171 行），该提交被合并到了 `linux原生编译模型llama.cpp` 分支。

**修复**：
```bash
cd /root/autodl-tmp/agent-system
git checkout b4faca7 -- Agent1.Api/Program.cs   # 恢复到干净版本（582 行）
```

---

### 2.4 API 启动缺少环境变量

**现象**：`nohup dotnet run --project Agent1.Api` 后进程 Exit 1，日志无监听输出。

**根因**：`DOTNET_ENVIRONMENT=Production` 下，`JWT_KEY` 和 `DB_PASSWORD` 是必选环境变量。

**修复**——启动命令必须带环境变量：
```bash
DOTNET_ENVIRONMENT=Production \
DB_PASSWORD=7758521 \
JWT_KEY=qazwsxedcrfvtgbyhnujmikolpqazwsx \
nohup dotnet run --project Agent1.Api/Agent1.Api.csproj -c Release ...
```

---

### 2.5 Kestrel 端口无监听（最关键）

**现象**：
- 日志显示 `化工合规 AI Agent API 已启动`，配置摘要正常
- 进程 `ps aux` 存在（PID 2076/2588）
- 但 `curl localhost:5000` → `Connection refused`
- `ss -tlnp` / `netstat` 均无 5000 端口

**根因**：`.NET 8 Production 模式` 下，`launchSettings.json` 配置了 HTTPS 端点（5001），Kestrel 尝试绑定 HTTPS 但无有效开发证书，导致**静默放弃 HTTP 绑定**——进程不崩溃、不报错、日志只输出 "developer certificate is not trusted"，但不监听任何端口。

**验证关键线索**：
```
[14:24:46 WRN] The ASP.NET Core developer certificate is not trusted.
```

**修复**——强制跳过 launchSettings.json，显式指定 HTTP：
```bash
nohup dotnet run --project Agent1.Api/Agent1.Api.csproj -c Release \
  --urls http://0.0.0.0:5000 --no-launch-profile \
  > /root/autodl-tmp/logs/agent1-api.log 2>&1 &
```

> ⚠️ 单纯设置 `ASPNETCORE_URLS=http://0.0.0.0:5000` **不够**——`launchSettings.json` 优先级高于环境变量，必须用 `--no-launch-profile` 禁用。

## 三、最终正确的完整启动流程

```bash
# ── 1. PostgreSQL ──
su - postgres -c "pg_ctlcluster 16 main start"
pg_isready

# ── 2. LLM 推理 (8080) ──
nohup /root/autodl-tmp/llama.cpp/build/bin/llama-server \
  -m /root/autodl-tmp/models/Qwen_Qwen3-8B-Q4_K_M.gguf \
  --host 0.0.0.0 --port 8080 -ngl 99 -c 8192 \
  > /root/autodl-tmp/logs/llama-server.log 2>&1 &

# ── 3. Embedding (8081) ──
nohup /root/autodl-tmp/llama.cpp/build/bin/llama-server \
  -m /root/autodl-tmp/models/nomic-embed-text-v1.5.f16.gguf \
  --host 0.0.0.0 --port 8081 --embeddings -ngl 99 -c 2048 --batch-size 512 \
  > /root/autodl-tmp/logs/llama-embed.log 2>&1 &

sleep 5

# ── 4. Agent1 API (5000) ⚠️ 必须带 --no-launch-profile ──
cd /root/autodl-tmp/agent-system
DOTNET_ENVIRONMENT=Production \
DB_PASSWORD=7758521 \
JWT_KEY=qazwsxedcrfvtgbyhnujmikolpqazwsx \
nohup dotnet run --project Agent1.Api/Agent1.Api.csproj -c Release \
  --urls http://0.0.0.0:5000 --no-launch-profile \
  > /root/autodl-tmp/logs/agent1-api.log 2>&1 &

sleep 12
curl http://localhost:5000/health/live    # → {"alive":true}
```

## 五、经验教训

1. **AutoDL 容器环境差异**：无 systemd、无 `ss`/`netstat` 命令，需用 `pg_ctlcluster` + `/proc/PID/net/tcp` 替代
2. **Kestrel HTTPS 静默失败是隐蔽陷阱**：进程存活、日志正常、但端口不监听——唯一线索是 "developer certificate not trusted" 警告
3. **--no-launch-profile 是生产裸机部署的必需品**：launchSettings.json 的 HTTPS 配置在无证书环境中会阻止 HTTP 绑定
4. **Git 分支污染**：在一个分支上的损坏提交可能通过 merge/rebase 污染其他分支，需用 `git checkout <good-commit> -- <file>` 精准恢复
5. **环境变量不可省略**：`JWT_KEY` 在 Production 模式下是强制校验项，缺失会导致进程 Exit 1
