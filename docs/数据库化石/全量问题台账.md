### #1 audit_logs.module 字段全空

**发现**：全量分组统计 `count(*) FILTER (WHERE module IS NOT NULL)` = 0/1189

**根因**：`IAuditService.LogOperationAsync`、`IDatabaseService.AddAuditLogAsync` 两个接口签名里都没有 `module` 参数，只有建表 SQL 预留了列

**影响**：审计的"在哪个功能里干的"维度完全缺失，无法按功能模块筛选审计记录

**修复方案**（待讨论）：
- 方案 A：给接口加 `module` 参数，所有调用点补传（工作量大，影响全链路）
- 方案 B：保持现状，从 action/detail 里推断功能归属（不修表结构，接受设计残留）
- 方案 C：标记为废弃列（`COMMENT ON COLUMN audit_logs.module IS 'DEPRECATED: 接口未实现'`）

**核销验证 SQL**（待修复后执行）：
```sql
SELECT count(*) FILTER (WHERE module IS NOT NULL AND module <> '') AS module有值,
       count(*) AS 总行数 FROM audit_logs;
-- 预期：module有值 > 0（证明修复后开始写入）
```

```
1. 发现问题 → 记录到台账（状态 🔴）
2. 分析根因 → 追到代码行号（状态 🟡）
3. 制定修复方案 → 评审选择（状态 🟡）
4. 执行修复 → 代码修改 + 测试
5. 回查数据库 → 跑核销验证 SQL（状态 🟢 或 ⚪）

```

- 禁止仅凭代码推断"修好了"——必须跑 SQL 回查数据库（宪法第三条：真实数据落地）
- 禁止跳过步骤 5 直接标记核销（防幻觉）
