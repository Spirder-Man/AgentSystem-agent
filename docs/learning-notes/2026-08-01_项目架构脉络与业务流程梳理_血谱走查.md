## 二、L1 HTTP 层：Agent1.Api

### 2.1 中间件管线（按注册顺序，10 个节点）

```
请求进入
 ① HTTPS 重定向 + HSTS（仅生产）
 ② GlobalExceptionMiddleware      ← 最外层兜底：捕获下游一切未处理异常
 ③ RequestIdMiddleware            ← 请求 ID 透传（全链路追踪锚点）
 ④ RateLimitingMiddleware         ← 100 次/分钟/IP+端点 组合限流
 ⑤ RequestMetricsMiddleware       ← 指标采集（MetricsCollector）
 ⑥ Swagger / SwaggerUI
 ⑦ CORS（默认 localhost:3000/5173，生产由 CORS_ORIGINS 控制）
 ⑧ Authentication                 ← JWT Bearer 认证（MapInboundClaims=false）
 ⑨ TokenBlacklistMiddleware       ← 黑名单检查（必须在认证后、授权前）
 ⑩ Authorization                  ← 三策略：Admin / Auditor / Viewer
 → MapControllers
```

**权限三策略**：`Admin`=admin 仅；`Auditor`=admin+auditor；`Viewer`=admin+auditor+viewer。查询类多为 Viewer，**写操作（审核/扫描/更新/评测/工单流转）一律 Auditor+**。

## 三、L2 核心层：Agent1（大脑）

### 3.1 AgentDialog：6 步统一线性流水线

```
用户输入
 ┌─ [1/6] 预处理          PreprocessAsync：Trim 清洗
 ├─ 安全闸门               SafetyGuardService.ValidateInput：Prompt 注入检测（拦截即 Blocked）
 ├─ [2/6] 意图路由         IntentRouter.Route：关键词匹配，记录 LastMatchedKeyword（可审计）
 ├─ [3/6] 上下文加载       LoadContextAsync：会话历史(10条) + 短期记忆关键事实 + 用户画像
 ├─ [4/6] 业务执行         ExecuteBusinessWithResultAsync（见 3.2）
 │                          └─ 输出末端：OutputSanitizer → OutputValidator 法规白名单 → 输出安全检测
 ├─ [5/6] 会话保存         SaveSessionAsync：写入 sessions 表
 └─ [6/6] 输出格式化       FormatOutput：展示文本
 审计留痕：ChemicalCompliance 意图 → audit_logs + ComplianceAuditLogger
```

### 3.2 业务执行层（第 4 步展开）

**前置记忆层**（MemoryCoordinator 预推理）：
- 缓存/记忆命中 → 仅当"来源=真实工具调用"才跳过 LLM（防兜底文本被缓存误答）
- 长期记忆命中 → 注入上下文（跨会话参考）；短期记忆命中 → 注入但不跳过推理

**ChemicalCompliance 分支（SK Auto Function Calling）**：

```
提示词组装（system + 历史 + 问题 + 输出模板）
 → LlmService.InvokeStreamWithRetryAsync（流式）
    ├─ 熔断器检查：3 连败 → 30 秒冷却 → 规则引擎降级
    ├─ FunctionChoiceBehavior.Required()：强制工具调用
    └─ 流式输出 + 死循环检测（重复行>8 / 级联字符>12 / 5000 字符硬截断）
 → LLM 失败 / 零工具调用 → TryFallbackToRuleEngine（确定性规则引擎兜底）
 → 双通道解耦管线（开关控制，见 3.5）
 → OutputValidator 法规白名单硬校验（非库内法规号标注"待核实"）
 → 记忆后推理（PostInferenceAsync 异步不阻塞）
 → 审计留痕
```

**SimpleChat 分支**：通用对话提示词 + SK 系统工具（GetCurrentTime/Calculate）收集。

### 3.3 LlmService 与 llama.cpp 的交互模式

| 维度 | 机制 |
|---|---|
| 协议 | Semantic Kernel `AddOpenAIChatCompletion(ModelId, Endpoint)`（`LlmService.cs#L67`）→ llama.cpp OpenAI 兼容端点 `/v1/chat/completions`（ModelConfig.Endpoint） |
| 工具 | `ChemicalComplianceTools` 插件注册（13 个 `[KernelFunction]`），SK Auto FC 由 LLM 自主决定调用 |
| 推理并发 | `SemaphoreSlim(2,2)` 单例闸门（API 层）+ 熔断器（进程内 3 连败/30 秒） |
| Thinking | Qwen3 思考模式开关：`EnableThinking`（默认 false，主流程临时切 true；OllamaThinkingHandler 反射注入 SK HttpClient） |
| 重试 | `MaxRetries`/`RetryDelayMs` 配置驱动；2 分钟超时兜底 |
| 防呆 | 流式死循环检测（重复行/括号级联/硬截断）；think 标签过滤（仅 DeepSeek-R1） |
| Embedding | llama.cpp `/v1/embeddings`，**批量数组请求**（一次多句），并发受 `MaxConcurrentEmbeddings` 控制 |
| 诊断 | `FunctionCallDiagnosticsFilter` 拦截器 → `LastFunctionCalls`（供评测/审计/验证层） |

**13 个工具（ChemicalComplianceTools）**：CheckHazardCategory、CheckStorageCompatibility、GetSafetyDistance、LookupChemicalProperties、GetMajorHazardThreshold、CheckRegulationVersion、LookupHazardLabel（多模态）+ 别名归一化辅助 + GetCurrentTime/Calculate 等系统工具。每个工具内部都是**三级降级**（见 3.6）。

### 3.4 ChemicalRAG：知识加载与混合检索

**文档入库管道**（全格式）：

```
knowledgebase/ 目录扫描
 → PdfExtractor / DocExtractor（PDF/DOC/DOCX/TXT 提取）
 → TextCleaner（清洗）
 → 乱码闸门（GarbledTextDetector 拒收乱码块）
 → SemanticChunker（语义分块）
 → 双存储：PostgreSQL（knowledge_documents + knowledge_chunks + 向量）+ 内存索引（BM25）
 扫描件 PDF（文本层过薄）→ PdfOcrService 视觉 OCR 回退（llama.cpp 视觉模型，可配置开关）
```

**增量更新**（Bug-038/039 修复后的正确形态）：`_incrementalGate`（static 信号量）`WaitAsync(0)` 拿不到 → `IncrementalAlreadyRunningException` → 409；绑定 `ApplicationStopping` 停机取消；文件追踪器（`LoadFileTracker`）只处理新增/修改/删除。

**检索三步**（`SearchAsync`）：
1. `RetrieveAsync(query, topK*3)`：HybridKnowledgeBaseService 内 查询缓存 → 查询扩展（ExpandQuery）→ 按模式（Bm25 / Vector / Hybrid-RRF 融合）检索
2. **优先级重排序**（核心修复）：`RegulationType` 加权——国标+3000 / 化工专业条例+2800 / 园区规则+2000 / 历史案例+1000 / 企业制度+500
3. 取 topK 返回

### 3.5 双通道解耦管线（Citation 准确率整改核心）

```
LLM 原始输出 + 工具调用记录
 → ComplianceFactExtractor：从工具返回提取结构化事实（法规号等）
 → OutputSanitizer：从 LLM 输出中删除 LLM 自编的法规引用（LLM 只负责专业解读）
 → FactAssembler：用工具事实确定性渲染法规引用段落
 → ResponseMerger：合并为最终答案
```

开关：`/admin/config/decoupled-architecture` 热切换；`UseDecoupledArchitecture=true` 时 LLM 用消毒后的输出模板（`OutputTemplateDecoupled`）。

### 3.6 确定性知识三级降级（工具内部）

```
Level 1: SQLite 结构化数据库（ChemicalDatabaseService —— 权威数据源，C# 种子 + 002_*.sql 双源同构）
Level 2: ChemicalSubstanceDatabase 静态字典（知识图谱门面注入）
Level 3: 硬编码字典（评测集对齐兜底）
末级:    诚实声明（"未找到"而非编造）
```

### 3.7 记忆系统（三层）

| 层 | 服务 | 要点 |
|---|---|---|
| 短期记忆 | MemoryService（会话内） | KeyFacts 提取/注入；`/memory/stats`、`/memory/clear` |
| 长期记忆 | LongTermMemoryService（跨会话） | 关键词检索、180 天清理；落库 `long_term_memories` 表 |
| 协调器 | MemoryCoordinator | 预推理（缓存判定）+ 后推理（异步写入）；与 ResponseCacheService 联动 |

## 五、四条核心业务线完整链路

### 业务线 1：合规自查（最高频）

```
ComplianceCheckPage
 → POST /api/compliance/check {query}
 → [中间件] JWT认证 → 授权(Auditor)
 → ComplianceController.CheckCompliance
    ├─ SafetyGuardService.ValidateInput（Prompt 注入拦截）
    ├─ ResponseCacheService.Get（命中直接返回）
    ├─ _llmGate.WaitAsync(5s)（超限 503+retryAfter:10）
    ├─ AgentDialog.ExecuteEvalFastAsync（评测快速通道：跳过流水线装饰，直调 LLM）
    │    └─ LlmService：SK FC Required → llama.cpp 推理
    │         └─ 工具调用：CheckHazardCategory 等 → SQLite→字典→RAG（HybridKnowledgeBaseService）
    │              └─ 双通道渲染（FactExtractor→Sanitizer→FactAssembler→Merger）
    ├─ ConclusionVerifier.VerifyAsync（法规号验证：库内白名单/幻觉标注）
    ├─ SafetyGuardService.ValidateOutput（输出高危断言检测）
    ├─ IntegrationService 外部系统查询（未接入显式降级，不阻断主流程）
    ├─ 审计留痕（audit_logs）
    └─ _cache.Set（写缓存）
 → 200 {response, toolsUsed, verifiedRegulations, warnings}
```

### 业务线 2：应急响应

```
EmergencyPage（化学品 + 事故类型 leak/fire/explosion/poisoning）

 → EmergencyController（Viewer 权限）
    ├─ 英文枚举 → 中文事故类型映射
    ├─ 组装 EmergencyScenario（默认 100kg）
    ├─ EmergencyResponseService.GeneratePlanAsync
    │    ├─ 知识库检索（化学品属性：CAS/UN/危险类别/闪点）
    │    ├─ LLM 生成方案（疏散隔离/PPE/应急处置措施）
    │    └─ 审计留痕
    └─ FormatEmergencyPlan 文本格式化（隔离半径/防护行动区/PPE 等级…）
 → 200 {output}
```

### 业务线 3：知识库查询（RAG 链路）

KnowledgeBasePage

```

```
