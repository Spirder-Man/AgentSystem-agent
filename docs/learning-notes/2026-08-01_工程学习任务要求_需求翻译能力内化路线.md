> 立约日期：2026-08-01
> 性质：个人工程学习任务书（必须达到，非可选）

## 二、内化目标：汽车制造厂自动化需求（目标态样例）

> 本样例是"成熟工程师拿到需求后的完整思维过程"，用于校准方向——先看见正常态，再对照差距。

### 2.1 需求原文

> 为一家汽车制造厂设计自动化生产管理系统：从订单到整车下线，产线自动化、质量可追溯、异常秒级响应。

### 2.2 第一步：拆业务流程（先不问技术，先问业务）

```
订单 → 排产 → 来料/仓储 → 冲压 → 焊装 → 涂装 → 总装 → 质检 → 下线/发运
         │        │          │       │       │       │      │
     产能约束   BOM缺料    设备状态  工艺参数  节拍   装配追溯  缺陷检测
```

每个环节先问三个问题：**做什么？依赖什么？受什么约束？**

| 环节 | 做什么（动词） | 依赖什么（资源） | 约束（规则） |
|---|---|---|---|
| 排产 | 订单拆工单 | 产能数据、物料 BOM | 产能有限、物料有限 |
| 来料 | 库存校验 | 仓储数据 | 缺料要预警 |
| 冲压/焊装/涂装 | 生产执行 | 设备状态、工艺参数 | 设备节拍限制 |
| 质检 | 缺陷检测 | 图像、标准库 | 标准来自权威（国标/企标），不能编 |
| 追溯 | 记录全程 | 各环节数据 | 记录不可篡改 |
| 异常 | 停线/报警 | 实时数据 | 秒级响应 |

### 2.3 第二步：抽业务角色（对应服务边界）

| 业务角色 | 领域服务 | 状态特征 |
|---|---|---|
| 计划域 | 排产服务（订单→工单） | 无状态，规则计算 |
| 执行域 | 工单服务（状态机：待排产→生产中→质检中→完成） | 有状态（工单流转） |
| 质量域 | 质检服务（规则 + AI 视觉） | 无状态服务 + GPU 资源 |
| 物料域 | 仓储服务（库存/BOM 校验） | 有状态（库存数） |
| 设备域 | 采集服务（设备数据） | 高吞吐写入 |
| 追溯域 | 追溯服务（台账） | 只追加，不可篡改 |

### 2.4 第三步：约束 → 机制翻译（核心动作）

| 业务约束 | 翻译成什么机制 | 本项目已内化的对照 |
|---|---|---|
| 产线不能同时处理超过 N 个工单 | 并发闸门（SemaphoreSlim 单例） | `_llmGate` 2 并发/503 |
| 追溯记录不可篡改 | 哈希链（链式校验） | AuditService 哈希链 |
| 质检标准必须来自权威标准 | 三级降级瀑布（权威库→缓存→兜底） | SQLite→PG→硬编码字典 |
| 质检图像缺陷识别 | AI 视觉模型（GPU 推理） | PdfOcrService :8083 Qwen2.5-VL |
| 停线判断必须秒级、不能等 AI | 确定性规则引擎优先 | DeterministicRuleEngine |
| 重复质检不重复跑 AI | 响应缓存（分级 TTL） | ResponseCacheService |
| 工单状态不能乱跳 | 状态机（确定性流转） | TicketsController 状态机 |
| 设备日志百万行可检索 | 结构化日志（Serilog） | 远程排障 34 个日志文件 |
| 工艺数据每秒采集不丢 | 消息队列/批量落库 | 增量加载互斥 + 批末落盘 |

### 2.5 第四步：技术路线图（分阶段，每阶段一个可验收闭环）

| 阶段 | 交付 | 技术栈 | 对应本项目已学 |
|---|---|---|---|
| M1 | 订单→工单→质检 最小闭环 | Web API + 关系库 + 规则引擎 | Agent1.Api + SQLite + ComplianceRuleEngine |
| M2 | 设备采集 + 实时看板 | 消息队列 + 时序存储 + 信号R | 日志管道 + 指标中间件 |
| M3 | AI 视觉质检 + 追溯链 | GPU 推理 + 哈希链 | OCR 支线 + 审计哈希链 |
| M4 | 排产优化 + 预测维护 | 算法模型 | 评测引擎（离线验证） |

### 2.6 第五步：技术图（三层器官，与本项目同构）

```
前端看板/移动端 → API层（工单/质检/追溯/设备 Controller）
  → 核心层（排产服务 / 工单状态机 / 质检服务 → AI视觉+规则引擎 / 追溯服务）
  → 存储层（关系库 + 时序库 + 追溯链文件）
```

## 三、翻译方法论（固化工具，练习时必须使用）

### 3.1 翻译公式表

| 业务世界 | DI 世界 |
|---|---|
| 业务名词 | 服务/类 |
| 业务动作 | 方法 |
| 业务协作 | 依赖图（构造器注入） |
| 资源约束 | 生命周期（单例/作用域/瞬时） |
| 业务规则 | 领域服务纯方法 |
| 横切约束（日志/审计/校验） | 静态工具/中间件 |

### 3.2 三清单法（每个需求必出三张清单）

```
① 角色清单（Who）：入口角色 / 执行角色 / 资源角色 / 工具角色
② 关系清单（How）：谁依赖谁？哪些共享？哪些请求隔离？
③ 约束清单（Constraints）：每条业务约束 → 翻译成什么机制？
```

### 3.3 机制 = 约束反推表（阅读代码时的反向练习）

读代码看到一个机制，必须能回答："**它翻译的是哪条业务约束？**"
答不上来 → 登记盲点 → 第二宪法自研。

## 四、练习制度（必须达到的要求）

### 4.1 练习流程（预测-验证法，每次必须完整走完）

```
① 选一条未读业务线（血谱定位）
② 只看血谱描述 + Controller 签名 → 凭直觉"翻译"出 DI 设计
   （角色清单 / 关系清单 / 约束清单 / 生命周期预测）
③ 读代码验证预测
④ 差异 = 认知盲区 → 记入学习笔记（必须含：我预测了什么、代码真相是什么、为什么错）
⑤ 差异涉及图码不符 → 回写血谱
```

### 4.2 练习频率与顺序（本项目 4 条业务线）

| 顺序 | 业务线 | 练习类型 | 状态 |
|---|---|---|---|
| 1 | 合规审核 P0 | 已完成 Controller 矩阵 | 🔄 下一步：AgentDialog 双路径翻译 |
| 2 | 应急响应 P2 | **第一次完整预测-验证** | ⬜ 待开始 |
| 3 | 知识库 P1 | 预测-验证 | ⬜ |
| 4 | 审计 P3 | 机制反推（哈希链=不可篡改约束） | ⬜ |
| 5 | 底层机制 | 并发锁（已归档）/ DI 生命周期 / 信号量 | 🔄 |

### 4.3 验收标准

- 每条业务线练习产出"四清单 + 差异记录"
- 连续 3 次预测命中率 ≥ 70% → 进入 L3 阶段（外部需求练习）
- 外部需求练习：用三清单法翻译 3 个陌生场景（汽车厂/医院/物流）→ 达成 L3

## 五、学习纪律（对齐既有规则）

1. **血谱前置**：任何练习先读血谱定位血管，读完差异必须回写
2. **第一宪法**：正常基准先行——先看成熟形态（如汽车厂样例），再对照差距
3. **第二宪法**：底层疑惑自研吃透——机制看不懂就复现，四要素归档
4. **不贪多**：一次一条血管，一条链路走到底
5. **不写 scripts/**：练习产出进 Agent1.Tests/ 或 docs/learning-notes/
6. **技术服务于业务**：任何机制先问"它翻译了哪条约束"，答不出就是没内化
